## Transfer partial-copy policy

Host originals are never rewritten. Local OCI/CUDA/microVM copies extract into a unique `yougori-import-<id>` folder; partial guest content remains available for inspection and is not silently adopted as a complete copy. Full VM copies use a separate imported-files drive. Temporary host staging is deleted after workers release their handles; a blocked OS read may finish after cancellation and is reported as interrupted rather than safe completion.

SSH transfers use a hidden unpublished staging folder. Closing the stream causes the receiver to remove that unpublished staging; any unique copy already verified and published remains. A lost response after publication is an unknown outcome: inspect/reconcile the identity before retrying. Declarative file activation verifies prepared per-file checksums and atomically switches only a managed target; unrelated application paths are preserved.

Ordinary host exports retain completed files in a unique copy and remove the incomplete current file after its worker releases the file handle. Between-environment copies use private host staging and retain source and target cancellation through the export-to-import handoff. Both source and target Stop actions cancel the logical transfer. Staging is removed after workers release their handles. Archive exports publish only after a checksum/receipt is verified; unpublished host archives are removed when their handles close.

## Compatibility and verification limits

CLI and engine must be updated together for protocol 2. Existing guest runtimes need the rebuilt guest agent before using new transfer status, async execution and managed file activation endpoints. Runtime payloads have been rebuilt in this checkout; they have not been installed over the user's existing runtime.

True asynchronous execution is available in local OCI/CUDA containers and built-in agent microVMs. Other providers retain their explicit bounded execution interface; no uninstalled guest agent or SSH capability is implied. Public readiness requires a selected health probe. An authenticated probe can bind a vault reference without putting the credential into the manifest or ordinary output.

Failure tests use private stores, unique IPC endpoints and disposable runtimes. The D: CUDA test unregisters only its newly created, identity-verified stopped distribution. Existing user environments, public domains and installed binaries are untouched. Real saved-domain restoration and before-sign-in service operation are not claimed from the local fixtures; the latter remains a different unsupported startup promise.
